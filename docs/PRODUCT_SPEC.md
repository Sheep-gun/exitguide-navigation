# EGL Navigation 제품 명세 v1

## 1. 제품 정의

EGL Navigation은 사용자의 목적과 현재 Android 화면을 함께 이해하고, 검증된 모범 경로에 따라 다음에 선택할 실제 메뉴를 메시지형 플로팅 UI로 안내한다.

```text
대신 클릭하는 에이전트가 아니라
현재 화면을 이해하고 경로 이탈을 복구하는 실시간 내비게이션
```

## 2. 입력과 출력의 분리

### 화면 입력

- 기본: AccessibilityService의 UI 노드 트리
- 보조: 접근성 정보가 부족한 경우의 단일 스크린샷 비전 분석
- 수집 정보: 패키지명, 앱 버전, 화면 텍스트, Content Description, View ID, 역할, 클릭 가능 여부, 현재 좌표

### 사용자 출력

- 기본: 메시지형 플로팅 카드
- 예: `현재 화면에서 '구독 관리'를 누르세요.`
- 경고 예: `'혜택 계속 이용하기'는 구독 유지 경로입니다.`
- 좌표는 메시지 위치 설명이나 선택적 강조에만 사용한다.
- 자동 클릭과 자동 뒤로 가기는 수행하지 않는다.

## 3. 정상 안내 흐름

```text
1. 사용자가 플로팅 창에 목적 입력
2. K-EXAONE이 목적을 표준 goal_id로 변환
3. Upstage에서 검증된 모범 경로 후보 검색
4. AccessibilityService가 현재 화면 요소 수집
5. 현재 화면을 경로의 특정 상태에 매칭
6. 실제 화면 요소 중 안전한 다음 후보 선택
7. 사용자가 직접 해당 메뉴 선택
8. 화면 변경 후 예상 다음 상태인지 검증
9. 일치하면 다음 단계 안내
```

모델이 선택하는 `target_element_id`는 요청에 포함된 현재 `screen_elements` 중 하나여야 한다. 화면에 존재하지 않는 메뉴를 생성해 안내하지 않는다.

## 4. 경로 상태

```text
on_route           현재 화면과 모범 경로 단계가 일치함
reanchored         다른 단계 또는 경로 변형에서 현재 화면을 다시 찾음
recovery_required  안전한 복귀 행동을 사용자에게 요청해야 함
needs_review       후보가 있으나 안전하게 확정할 수 없음
route_not_found    해당 앱·목적의 검증 경로가 없음
goal_completed     목표 달성 화면이 확인됨
```

## 5. 경로 이탈 복구 순서

예상 다음 화면과 실제 화면이 다르면 다음 순서를 지킨다.

### 5.1 현재 화면 재정렬

현재 화면이 동일 경로의 다른 단계나 다른 결제 방식·앱 버전 경로에 존재하는지 먼저 확인한다. 일치하면 뒤로 가지 않고 해당 단계부터 안내를 계속한다.

### 5.2 알려진 우회 화면 처리

혜택 유지, 일시정지 제안, 광고성 팝업처럼 알려진 분기라면 모범 경로에 저장된 `닫기`, `취소`, `혜택 없이 계속` 같은 구체적인 탈출 메뉴를 안내한다.

### 5.3 안전한 복귀 요청

현재 화면을 어떤 검증 경로에도 매칭할 수 없고 해당 단계에 `recovery.safe=true`가 설정된 경우에만 사용자에게 복귀를 요청한다.

```text
현재 화면은 확인된 경로와 다릅니다.
이전 화면으로 한 번 돌아가 주세요.
돌아오면 다른 경로를 찾아 안내하겠습니다.
```

사용자가 뒤로 이동하면 AccessibilityService가 예상 이전 화면으로 복귀했는지 자동으로 확인한다.

### 5.4 대체 후보 탐색

복귀가 확인되면 실패한 요소 ID와 의미를 세션에서 제외하고 대체 후보를 찾는다. 대체 후보는 단순 검색 결과 2등이 아니라 다음 조건을 모두 충족해야 한다.

- 마지막으로 확인된 동일 화면에 실제로 존재함
- 모범 경로의 다음 행동과 의미가 일치함
- 클릭 가능한 요소임
- 실패한 후보와 다른 요소임
- 결제·가입·동의·삭제 같은 비가역 행동이 아님
- 예상 다음 화면이 정의돼 있음

### 5.5 추측 중단

기본 `max_retry`는 2회다. 첫 후보와 대체 후보가 모두 실패하면 추가 추측을 중단하고 `needs_review`를 반환한다. 알 수 없는 화면은 새 경로 버전 검수 대상으로 기록한다.

## 6. 복귀 안전성

다음 화면에서는 일반적인 뒤로 가기를 기본 복구로 사용하지 않는다.

- 작성 중인 회원가입·입력 폼
- 결제 또는 본인 인증 화면
- 최종 해지·탈퇴·삭제 확인 화면
- 외부 앱이나 브라우저로 이동한 상태
- 뒤로 이동했을 때 입력이나 상태가 소실되는 화면

이 경우 검증된 `닫기`, `취소`, `나중에` 메뉴가 있을 때만 안내하고, 없으면 진행을 중단한다.

## 7. 세션 상태

백엔드는 사용자별 내비게이션 세션에 다음 정보를 유지한다.

```json
{
  "last_confirmed_state_id": "membership_home",
  "failed_element_ids": ["node_21"],
  "failed_candidate_meanings": ["benefit_management"],
  "retry_count": 1,
  "route_variant": "google_play"
}
```

실패한 후보는 같은 세션에서 다시 제안하지 않는다. 앱이나 목표가 바뀌면 세션을 새로 시작한다.

## 8. 스크린샷 사용 조건

다음 중 하나일 때만 스크린샷 비전 분석을 요청한다.

- 접근성 트리가 비어 있음
- 텍스트 없는 아이콘·Canvas·자체 제작 UI
- 일부 WebView처럼 요소 정보가 불완전함
- 경로 상태 매칭 확신도가 기준보다 낮음
- 앱 업데이트로 새로운 화면이 감지됨

연속 영상 분석은 MVP 범위에 포함하지 않는다.

## 9. UI 업데이트 처리

```text
위치만 변경       현재 Accessibility 좌표를 사용하므로 경로 수정 불필요
문구 변경          의미 매칭 후 새 문구를 후보로 검수
중간 화면 추가     새 상태와 전환을 포함한 경로 버전 생성
결제 경로 변경     별도 route_variant 생성
전면 개편          안내 중단 후 새 경로 수집
```

운영 경로는 자동으로 덮어쓰지 않는다. 새 화면 관찰 → 사람 검수 → sandbox 검색 테스트 → prod 등록 순서를 따른다.

## 10. MVP 범위

- Android 대상 앱 3개
- 앱별 목적 2개 이상
- Accessibility 기반 현재 화면 인식
- 메시지형 플로팅 안내
- 사용자가 직접 클릭
- 정상 경로, 알려진 우회 경로, 안전한 복귀와 대체 후보 처리
- 후보 2회 실패 시 안전하게 중단
- 스크린샷 분석은 접근성 실패 시에만 사용
